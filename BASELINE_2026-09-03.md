### 2. `tests/test_task2_pg_harness.py` — FAIL(1), **schema mismatch**

```
psycopg2.errors.NotNullViolation: null value in column
"has_held_paid_entitlement" of relation "users" violates not-null constraint
```

Root cause — a genuine pre-existing inconsistency in the Task 8 entitlement
schema, reachable only on Postgres:

- `app/models/user.py:31` declares
  `has_held_paid_entitlement = Column(Boolean, default=False, nullable=False)`
- `app/database.py:597` migrates it as
  `ALTER TABLE users ADD COLUMN IF NOT EXISTS has_held_paid_entitlement BOOLEAN DEFAULT FALSE`
  — **`DEFAULT FALSE` without `NOT NULL`**

The harness inserts users with raw SQL that omits the column, so Postgres
stores `NULL`, and the model's NOT-NULL expectation rejects the row.
SQLite-backed suites don't hit it because the column is created from the
model's own metadata there.

**Out of scope for the growth-profile feature** (Task 8 entitlement schema,
not profiles). Worth a separate follow-up: either add `NOT NULL` + a
backfill to the migration, or relax the model to `nullable=True`. Note the
same class of mismatch is what `verify_required_schema()` exists to catch —
this column is evidently not in its registry.

**Expected state after growth-profile work: still failing, identically.**
